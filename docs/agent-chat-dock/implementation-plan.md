# Agent Dock control-plane implementation plan

## Goal

Upgrade the existing native Agent Dock from a profile-scoped job launcher into a truthful control surface that can attach to a real live Hermes run and safely communicate without restarting, replacing, or duplicating it.

## Product invariants

1. Opening the Dock is read-only and never starts, resumes, interrupts, or duplicates a run.
2. Live attachment requires an exact profile + gateway session + run binding. A matching display name is insufficient.
3. ASK is read-only intent. It must not be represented as task modification.
4. NUDGE uses Hermes `session.steer` or `subagent.steer`, never an unsafe mid-tool synthetic user insertion.
5. REDIRECT requires explicit confirmation and uses `session.redirect`; it is distinct from Stop.
6. Stop requires confirmation and uses `session.interrupt`; the UI discloses that queued prompts are cleared and pending approvals denied.
7. Pause/Resume remains unavailable until Hermes exposes a verified per-run pause contract.
8. A message is never `applied` merely because the HTTP request or JSON-RPC request succeeded.
9. Every mutation has a stable client request ID and idempotent durable receipt.
10. Interventions cannot expand the selected profile/run's tools, credentials, write roots, model authority, or approval policy.
11. NUDGE, REDIRECT, and Stop create an orchestrator-visible event when a Kanban task is bound. Failure to synchronize is surfaced, not hidden.
12. Private transcript bodies, credentials, and raw external destination identifiers are excluded from projections and logs.

## Architecture

```text
Agent Dock plugin.js
  ├─ host.request('session.active_list') -> truthful live run inventory
  ├─ host.request('delegation.status') -> live delegated run inventory
  ├─ host.request('session.steer|redirect|interrupt') -> native control mutation
  ├─ host.request('verification.status') -> proof projection
  └─ ctx.rest('/control/...') -> durable control records
          ↓
control_store.py (SQLite under active HERMES_HOME/agent-dock/control-plane.sqlite3)
  ├─ runs: canonical profile/session/subagent/task binding + observed state
  ├─ messages: run-scoped ASK/NUDGE/REDIRECT/STOP requests
  ├─ receipts: append-only lifecycle and application evidence
  └─ events: searchable redacted run ledger
```

The renderer is the bridge because `host.request` is the supported Desktop gateway transport and `ctx.rest` is the supported plugin backend transport. No parallel network service is introduced.

## Durable schema

### runs

- `run_id` TEXT primary key, generated by Agent Dock.
- `profile` TEXT required.
- `session_id` TEXT required for session controls.
- `subagent_id` TEXT nullable.
- `kanban_task_id` TEXT nullable.
- `source` TEXT (`desktop-session`, `subagent`, `dock-job`).
- `objective` TEXT nullable, bounded/redacted projection only.
- `status` TEXT (`starting`, `working`, `waiting`, `stopped`, `completed`, `unavailable`).
- `created_at`, `updated_at`, `heartbeat_at` integer epoch seconds.
- Unique binding across `(profile, session_id, subagent_id, kanban_task_id)`.

### messages

- `message_id` TEXT primary key; client-generated idempotency key.
- `run_id` foreign key.
- `kind` TEXT (`ask`, `nudge`, `redirect`, `stop`).
- `body` TEXT bounded to the Dock message limit; never included in list projections unless explicitly requested for the selected run.
- `body_sha256` TEXT.
- `state` TEXT (`queued`, `dispatching`, `accepted`, `delivered`, `applied`, `rejected`, `failed`, `superseded`).
- `confirmed_at` required for redirect/stop.
- `created_at`, `updated_at`.
- `dispatch_token` and lease timestamp for crash-safe claim/retry.

### receipts

- `receipt_id` TEXT primary key.
- `message_id` foreign key.
- `stage` TEXT.
- `verification_state` TEXT (`observed`, `reported`, `unverified`, `failed`).
- `source` TEXT (`agent-dock`, `hermes-gateway`, `kanban`, `verification-ledger`).
- `source_id` optional bounded opaque ID.
- `detail` bounded/redacted JSON.
- `created_at`.
- Unique `(message_id, stage, source, source_id)` for retry idempotency.

### events

- Append-only event ID, run ID, message ID, kind, redacted detail, timestamp.
- Indexed by run/time and kind/time.

SQLite uses WAL, foreign keys, bounded busy timeout, explicit transactions, additive schema versioning, and profile-local `get_hermes_home()`.

## API

- `GET /control/runs` — durable bindings plus source availability.
- `POST /control/runs/attach` — idempotently bind an observed live gateway session/subagent/task.
- `GET /control/runs/{run_id}` — selected run, state, history, receipts, and events.
- `POST /control/messages` — idempotently enqueue ASK/NUDGE/confirmed REDIRECT/STOP.
- `POST /control/messages/{message_id}/claim` — lease a queued mutation for Desktop gateway dispatch.
- `POST /control/messages/{message_id}/receipt` — record gateway acceptance/rejection/application evidence with transition validation.
- `GET /control/runs/{run_id}/events?q=&kind=` — searchable bounded history.
- `POST /control/runs/{run_id}/observe` — update truthful state/heartbeat/proof from Desktop observations without inventing progress.

## Dispatch mapping

- ASK on idle selected session: use normal `session.send` only when the operator explicitly sends a new turn; ASK during a running turn is queued until idle because injecting a question into a running task would modify its context.
- NUDGE: `host.request('session.steer', {session_id, text})`; a subagent target uses `subagent.steer` and includes the invoking owner session.
- REDIRECT: require confirmation, then `host.request('session.redirect', {session_id, text})`.
- STOP: require confirmation, then `host.request('session.interrupt', {session_id})`.

A successful RPC records `accepted` with the exact returned status. `applied` requires a later explicit event/agent response referencing the message ID. Where Hermes emits no such event, the state remains `accepted` or `delivered`; the limitation is visible.

## Orchestrator synchronization

For a run bound to `kanban_task_id`, the backend appends a redacted comment and event for NUDGE, REDIRECT, STOP, and their receipts. It never auto-completes a task. Sync failure records `orchestrator_sync_failed` and keeps the original message state.

For an unbound run, synchronization is `UNAVAILABLE: no durable orchestrator task binding`. The Dock does not invent a card for an ordinary ASK/NUDGE. The operator may explicitly bind or assign one.

## UI slice

1. Agent selector includes an observed live-state badge.
2. Run selector lists exact live sessions for the selected profile; attachment is explicit.
3. Header shows source, run ID suffix, status, heartbeat freshness, task binding, and proof state.
4. Composer mode control: ASK / NUDGE / REDIRECT.
5. REDIRECT opens a confirmation dialog describing objective-change impact.
6. Stop is a separate confirmation control. Pause is disabled with the truthful unavailable reason.
7. Each operator message renders durable receipt stages; accepted is not labelled applied.
8. A compact state/proof disclosure shows task ID, current action when observed, blocker, verification status, and unavailable reasons.
9. Existing new-job chat remains available only when no live run is attached.

## Tests

### Store/unit

- temp-HERMES_HOME schema creation and reopen persistence.
- legacy/empty startup and additive migration.
- exact run binding idempotency and cross-profile isolation.
- duplicate message ID returns the original row without a second event.
- redirect/stop rejected without confirmation.
- invalid transitions rejected; terminal receipts immutable.
- claim lease expiry/recovery; concurrent claim has one winner.
- event search bounded and redacted.
- unknown records survive reconciliation.

### Backend integration

- attach only validated profiles and session IDs.
- permission metadata cannot be supplied or widened by a request.
- Kanban sync creates comments/events but never completes a task.
- sync failure is explicit and retains the intervention record.
- restart reloads queued/accepted history from SQLite.

### Frontend/state

- active-list normalization never treats profile name alone as attachment.
- ASK/NUDGE/REDIRECT payloads map to the correct methods.
- redirect and stop cannot dispatch without confirmation.
- queued/accepted/applied labels remain distinct.
- transient control API failures preserve the pending message ID.
- run switch keeps histories isolated.
- unavailable Pause and proof reasons render truthfully.

### Acceptance

- Attach to a deterministic live test session without starting a second run.
- Start a tool-using deterministic test turn; NUDGE is accepted while the tool executes and observed only at a later checkpoint.
- Retry the same message ID and prove one message/dispatch record.
- Restart the plugin backend and prove run history/receipts survive.
- Confirm REDIRECT confirmation and Stop confirmation.
- Confirm existing Hermes approvals still fire and no approval mode/tool configuration changes.
- Confirm bound Kanban task contains the intervention writeback.
- Capture sanitized floating and docked screenshots.

## Rollback

The installer already creates a timestamped backup. Rollback is:

1. Disable the plugin or run `python uninstall.py` for reversible removal.
2. Restore the prior plugin backup generated by `install.py` if reverting an upgrade.
3. Preserve `control-plane.sqlite3` by default; deleting operational history is never part of normal rollback.
4. Reinstall the previous tagged release and fully restart Hermes Desktop to remount its Python backend.

No Hermes core file or user profile configuration is modified by this plan.
