# Agent Dock v0.4 limitation-retirement roadmap

Status: active engineering plan

## Main goal

Turn the v0.3.0 control-plane prototype into a restart-tolerant, cross-surface Hermes operator while preserving exact profile/session/runtime binding and Dad-controlled consequential actions.

The items below are not all the same kind of problem. Some are Agent Dock implementation gaps, some require generic Hermes Desktop or gateway capabilities, and two are safety boundaries that should be improved rather than removed.

## Delivery order

### 1. Explicit exact-runtime rebind — first vertical slice

**Code-level status:** accepted on `feat/v0.4-limitations`. The implementation passed 68 Python tests, 30 Node tests, JavaScript syntax validation, and `git diff --check`. An independent bounded closeout returned **SHIP** with no P0/P1/P2 findings. This does not claim installation or live Desktop verification; those remain separate activation and runtime gates.

**Outcome:** after a Desktop restart, a durable control run can be explicitly rebound to a newly observed live runtime only when its profile and stable session identity match exactly.

**Why first:** this closes the highest-impact reliability gap that Agent Dock can own without model tokens, authority expansion, transcript merging, or speculative host infrastructure.

**Contract:**

- Rebinding is explicit; the Dock never silently reattaches.
- Match the selected profile, runtime profile, stable session ID, old runtime ID, and run ID transactionally.
- Replace only the ephemeral runtime ID; preserve the run, queued interventions, receipts, and events.
- Emit one privacy-reduced `run_rebound` event.
- A stale runtime cannot claim or receipt control messages after rebind.
- Unknown runtime profile fails closed; it must never fall back to `default`.
- REDIRECT and STOP are never replayed on reload.

**Proof required:** persistence across store reopen, compare-and-swap mismatch tests, stale-runtime refusal, exact stable-session candidate matching, explicit UI action, new-runtime NUDGE dispatch, and no use of the old runtime ID.

### 2. Durable active jobs across Desktop restart

**Observed gap:** active jobs live in the process-local `_JOBS` dictionary and run in daemon threads connected to child-process pipes. A complete Desktop exit loses the parent-side job state and result channel.

**Target:** replace process-owned execution with a durable job journal and a restart-reconcilable worker/spool contract.

**Required behavior:**

- Persist job intent and state before acknowledging submission.
- Keep prompts and credentials out of argv and public logs.
- Write partial/terminal worker results atomically to profile-local storage.
- Reconcile queued/running/finalizing jobs after backend restart.
- Preserve idempotent request IDs and cancellation semantics.
- Never report an orphaned job as completed without terminal worker evidence.

**Proof required:** forced backend restart during queued, running, finalizing, cancellation, and completed states; duplicate-start prevention; stale-worker recovery; privacy scan.

### 3. Token-level response streaming

**Observed gap:** Agent Dock starts `dock_runner.py`, waits on `Popen.communicate()`, and polls `/jobs/{id}`. The Hermes core already emits `message.delta` events and the plugin SDK exposes `host.onEvent`, but `host.request` and its event stream are bound to the active Desktop gateway profile. Agent Dock can select another profile.

**Target:** use one authoritative profile-aware live transport instead of fabricating partial text from polling.

**Decision gate:** choose between:

1. a generic profile-addressable gateway request/event capability in Hermes Desktop; or
2. a plugin-scoped WebSocket/SSE stream whose runner receives real Hermes `stream_delta_callback` events.

The first option gives stronger session/control unification. The second has a smaller core footprint but must reproduce lifecycle, cancellation, approval, and reconnect semantics carefully.

**Proof required:** real multi-chunk model response, tool-call interleaving, reconnect, cancellation, final-message dedupe, and non-active-profile isolation.

### 4. Intervention recovery after restart

**Safety invariant:** dispatch must still require a live Desktop gateway session with the exact runtime ID. A durable ledger is not authority to steer a different or reconstructed run.

**Target:** make pending state actionable without unsafe replay.

- Reconcile expired dispatch leases at startup.
- Show queued/accepted/delivered/applied states clearly.
- Permit explicit retry only after the exact live binding is re-observed.
- Never automatically replay REDIRECT or STOP after reload.
- Preserve NUDGE objective scope and ASK read-only behavior.

**Proof required:** reload at every receipt stage, expired lease recovery, runtime-ID mismatch refusal, and no REDIRECT/STOP replay.

### 5. Correlated application receipts

**Observed gap:** Hermes accepts steer/redirect requests but does not emit an event proving that a specific intervention changed a later plan. Agent Dock correctly stops at “Accepted by Hermes.”

**Target:** add a generic correlation identifier from intervention submission through the safe-checkpoint consumer and later plan/turn event.

**Contract:**

- “Accepted” means the gateway accepted the request.
- “Delivered” means the live turn consumed it at a safe boundary.
- “Applied” requires a consumer-originated event carrying the same correlation ID and evidence of incorporation.
- Agent Dock must never infer “Applied” from elapsed time or a later unrelated response.

**Proof required:** positive incorporation, accepted-but-not-applied, superseded, interrupted, duplicate, and wrong-session tests.

### 6. Per-run Pause/Resume

**Observed gap:** the current gateway supports steering, redirect, and interrupt, not a verified cooperative pause state for one active run.

**Target:** add gateway-owned pause/resume at safe checkpoints, not process suspension.

**Contract:**

- Pause blocks the next model/tool transition at a defined checkpoint.
- It does not freeze the whole gateway or hold locks indefinitely.
- Resume is idempotent and bound to the same runtime session.
- STOP remains distinct and confirmation-gated.
- Pending approvals and subprocess safety are explicitly defined.

**Proof required:** pause during model generation, between tool calls, while awaiting approval, resume after reconnect, and isolation from other sessions.

### 7. User-resizable floating panes

**Observed gap:** Hermes-native floating panes persist position and collapsed state but use contribution-defined width/height. The host implements header dragging, not user resize handles.

**Target:** a generic semantic host capability for opt-in pane resizing.

**Contract:**

- Contribution metadata supplies default/min/max size.
- The host owns resize handles, viewport clamping, persistence, keyboard accessibility, and collapse behavior.
- Existing panes retain fixed sizing unless they opt in.
- Agent Dock does not inject arbitrary host CSS or geometry code.

**Proof required:** pointer and keyboard resize, min/max clamping, viewport reflow, persistence, collapse/expand, dock/undock, and default-pane compatibility.

### 8. Pet-click activation

**Observed gap:** Agent Dock contributes to the string area `pet.actions`, but current Hermes Desktop does not expose a matching host consumer.

**Target:** add a generic pet action contribution area in Hermes Desktop and have the pet UI render validated plugin actions.

**Proof required:** supported-host click, missing-area fallback, plugin disable/unload cleanup, keyboard activation, and no loss of status-bar/command-palette launchers.

### 9. Model/provider scope UX

**Safety boundary:** a selected profile may use only providers and models that are configured and authenticated for that profile. This should not be bypassed.

**Target:** improve the limitation from a dead end into a guided workflow:

- Show why a provider/model is unavailable.
- Offer a safe route to profile setup/authentication.
- Refresh the catalog after an explicit configuration change or new session.
- Never expose credentials or make unauthenticated models appear runnable.

**Proof required:** configured provider, missing auth, expired auth, custom provider probe failure, and successful explicit refresh.

## Release gates

Each vertical slice must have:

1. a product contract and explicit non-goals;
2. focused backend and UI behavior tests;
3. an integration or live-path proof for the real boundary changed;
4. a privacy and secret scan;
5. independent review;
6. a clean branch containing no unrelated local work;
7. no public push, merge, tag, or release without Dad’s requested scope and the relevant evidence gate.

## Current status

- v0.3.0 durable control ledger: implemented.
- Host-owned semantic large floating radius: implemented on feature branches.
- Explicit exact-runtime rebind: code-level accepted after full regression checks and independent **SHIP** review; not installed or live-verified.
- Durable job restart reconciliation: implementation in progress in an isolated worktree; the first slice intentionally marks uncertain pre-restart attempts interrupted and never auto-replays them.
- An earlier explicit cross-channel-resume implementation was dispatched before that audit completed. Treat its output as a bounded feasibility spike only; do not integrate or publish it ahead of the rebind slice without a separate identity/leakage review.
- All other items: audited and ordered; not yet claimed complete.
